# CareerOS — Agentic AI Career Companion

React/TypeScript student workspace using TanStack Start, TanStack Router/Query, Vite, Tailwind, and the existing CareerOS design system. The public landing page remains intact; its entry buttons now open the functional dashboard.

## Run locally

Use Node 24 (`.nvmrc`) and npm:

```sh
npm ci
cp .env.example .env
npm run dev -- --host localhost --port 5173
```

Start the adjacent FastAPI backend using its README. Frontend configuration:

```dotenv
VITE_API_BASE_URL=http://localhost:8000/api/v1
```

This variable includes `/api/v1` and is public build-time configuration, not a secret. Rebuild when changing it for a production bundle. When absent, the client uses same-origin `/api/v1`, which requires a matching API reverse proxy. No localhost URLs are embedded in components. Use the same hostname for frontend/backend (both `localhost`, or both `127.0.0.1`) and a matching backend CORS origin.

## Routes and actual behavior

| Route | Status |
| --- | --- |
| `/` | Existing public landing page and illustrative product previews. |
| `/dashboard` | Live profile completion, document/skill counts, reviewed document-derived skills, verification, activity, and onboarding. |
| `/profile` | Create/update structured profile facts, individual skill rows with add/edit/remove controls, phone/links, revision conflicts, saved-fact confirmation, source documents, and verification timestamps. |
| `/documents` | Upload PDF/DOCX/TXT; start local extraction or explicitly consent to optional CrewAI/Groq processing; observe processing; review/edit source-linked fields; confirm selected sections, request correction, reject, cancel, retry, or remove. |
| `/settings` | Explains local identity, storage, cookie expiry, and current privacy/deletion limitations. |
| `/jobs` | Ten explicitly labeled seeded demonstration jobs; keyword/skill/location/remote/experience filters, pagination, and loading/empty/error/retry states. No applications or matching. |
| `/matches`, `/skill-gaps`, `/applications` | Explicitly planned; no fabricated rankings, applications, or agent activity. |
| `/workspace` | Preserved labeled sample demonstration, separate from the real workspace. |

`src/routes/_student.tsx` is a pathless layout. Its children create the URLs above. `routeTree.gen.ts` is generated by TanStack tooling; do not hand-edit it.

## API and identity

`src/services/api/client.ts` centralizes transport, timeout, cancellation, structured errors, and cookie credentials. Feature types and Query options are adjacent. Shared query keys avoid duplicate component requests; successful changes update cached records and invalidate dashboard summaries.

The client establishes an HttpOnly signed local browser session through `POST /api/v1/session`. This is not a production login. The backend derives ownership from the session. Clearing cookies or switching browser creates a different local workspace; it does not erase old database records. Recovery/account authentication is planned. Never put service keys in `VITE_*` variables.

Profiles, documents and dashboard data come from the real local backend: unavailable APIs show errors/retry controls, empty databases show empty states, and unimplemented metrics show a dash/planned label. The opportunities page uses an explicitly labeled seeded/mock dataset; public previews and legacy `/workspace` remain illustrative. Saving draft edits and confirming profile facts are separate actions. Extracted suggestions stay outside the profile until confirmation.

## Document review

Upload a readable resume, then choose **Process document**. Processing stays local by default. The optional CrewAI/Groq checkbox explicitly permits sending that document's extracted text, including contact details, to the backend-configured provider for that run. Configured runs execute the actual Resume Intelligence Crew. Agent metadata shows CrewAI processing, local-only processing, or an explicit fallback with its safe reason. Provider keys never reach this app. Missing keys, timeouts, rate limits, and invalid AI JSON retain real local extraction and show limited-mode warnings.

Review source quotes, heuristic confidence, and missing-field warnings. Expand sections to edit, then save draft edits. Select sections to apply and confirm accuracy before **Confirm and save profile**. Lists add unique entries; replacement requires an explicit choice. Different saved scalar values start unselected. Profile/draft revision conflicts require reload and renewed review. Edited values are labeled candidate corrections rather than claimed document quotes.

Only selected, confirmed sections reach the profile. Dashboard counts derive from stored profile facts and review receipts. Scanned PDFs fail with an OCR explanation and offer retry/manual entry. Full OCR, live job retrieval, matching, and the broader multi-agent career orchestrator remain planned. Local extraction handles basic headings/records and may miss complex layouts; the UI clearly labels its limits. Selection and replacement operate per top-level section, not per individual nested record.

## UI organization

- `components/workspace/WorkspaceLayout.tsx`: navigation, connection rail, content frame.
- `Dashboard.tsx`, `ProfilePage.tsx`, `DocumentsPage.tsx`, `JobsPage.tsx`, `SettingsPage.tsx`: functional screens.
- `SkillEditor.tsx`: individual add/edit/remove controls, Enter-key addition, duplicate/empty validation, origin/confirmation labels, and compatible bulk editing.
- `ResumeDetails.tsx`: optional structured education/work/project fields without crowding the main profile form.
- `DocumentReview.tsx`: processing polling, optional external-processing consent, source evidence, draft editing, selection/replacement, explicit confirmation, and recovery states.
- `shared.tsx`: panels, headings, loading/error/planned states, and dates.
- `hooks/use-panel-light.ts`: one delegated pointer listener with animation-frame updates; disabled for touch/coarse pointers and reduced motion.
- `workspace.css`: scoped layout/elevation/forms, existing rose palette, mobile drawer, and motion controls.

Velion inspired panel hierarchy, connection feedback, and pointer-light principles. Its domain code, assets, branding, and secrets are not part of this implementation.

## Checks

```sh
npm run typecheck
npm run build
npm run lint
```

Browser tests use both real local services. Start a disposable backend/database and the frontend first, then:

```sh
npx playwright install chromium
npm run test:e2e
```

`E2E_BASE_URL` defaults to `http://localhost:5173`. `E2E_API_BASE_URL` defaults to `http://localhost:8000/api/v1` for direct browser-test API checks; set both when using alternate isolated ports. `E2E_CHROMIUM_PATH` can select an installed Chromium executable for Chromium runs. The default browser is Chromium; use `E2E_BROWSER=webkit` for Safari-engine coverage after `npx playwright install webkit`. For example, `E2E_BROWSER=webkit npm run test:e2e`. Tests use isolated browser sessions and synthetic student fixtures. The 21 cases cover the original workspace plus actual document processing, source review, edits, confirmation/profile/dashboard integration, correction/rejection, scanned-PDF failure/retry, profile conflicts during review, and mobile review with reduced motion. They use local extraction or missing-key fallback and make no provider requests. Seeded-job tests cover all filters, pagination, source labels, loading, empty/error recovery and mobile layout; a consented missing-key run verifies visible fallback and local retry. Additional coverage checks full Objective text, separate projects/technologies, skill-object transport, multiple skill addition/edit/deletion, duplicates/empty input, persistence, save failure recovery, and explicit reprocessing without profile changes.

Database initialization, backend configuration, endpoint contracts, changed-file inventory, and limitations are documented in the adjacent backend's `README.md` and `docs/crewai-jobs-milestone.md`. A backend `.env` can set `GROQ_API_KEY_1`, `_2`, `_3`, `GROQ_MODEL`, `DOCUMENT_STORAGE_PATH`, and `MAX_DOCUMENT_SIZE_MB`; none belongs in this frontend's environment.

## Parser and evidence improvements

Documents now show a unified **Profile Summary / Objective** with the original section heading/type, complete statement text, grouped project bullets, entry-specific technologies, richer work/education details, and explicit not-detected/ambiguous states. Additional empty record fields are collapsed. Existing API fields remain compatible. Saved older reviews can explicitly **Reprocess with current parser**; the new review never changes the saved profile until confirmation.

The Profile page supports **Add Skill**, an input and Add action, Enter-key addition, individual edit/remove controls, duplicate/empty validation, and a compatible bulk editor. Skills remain a multi-value array. The API accepts skill objects on input and returns the legacy string list plus server-derived `skill_details`; client origin/verification claims cannot confirm a skill. Resume-derived skills retain their source when new manual skills are added. See the backend `docs/parser-quality-milestone.md` and reproducible `docs/extraction-evaluation.md` for the scoped evaluation and remaining limits.

## Safari date compatibility

Calendar dates from seeded jobs (`YYYY-MM-DD`) are converted to a complete ISO UTC timestamp before formatting. Backend timestamps retain their explicit offsets; timezone-free timestamps keep the existing UTC interpretation. Invalid dates display “Date unavailable” instead of crashing the route. The browser regression checks calendar dates, stored timestamps and invalid input in Chromium and WebKit.
