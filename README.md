# CareerOS — Agentic AI Career Companion

React/TypeScript student workspace using TanStack Start, TanStack Router/Query, Vite, Tailwind, and the existing CareerOS design system. The public landing page remains intact; its entry buttons now open the functional dashboard.

## Run locally

Use Node 24 (`.nvmrc`) and npm:

```sh
npm ci
cp .env.example .env
npm run dev -- --host localhost --port 5173
```

Start the adjacent FastAPI backend using its README. Frontend configuration:

```dotenv
VITE_API_BASE_URL=http://localhost:8000/api/v1
```

This variable includes `/api/v1` and is public build-time configuration, not a secret. Rebuild when changing it for a production bundle. When absent, the client uses same-origin `/api/v1`, which requires a matching API reverse proxy. No localhost URLs are embedded in components. Use the same hostname for frontend/backend (both `localhost`, or both `127.0.0.1`) and a matching backend CORS origin.

## API and identity

`src/services/api/client.ts` centralizes transport, timeout, cancellation, structured errors, and cookie credentials. Feature types and Query options are adjacent. Shared query keys avoid duplicate component requests; successful changes update cached records and invalidate dashboard summaries.

The client establishes an HttpOnly signed local browser session through `POST /api/v1/session`. This is not a production login. The backend derives ownership from the session. Clearing cookies or switching browser creates a different local workspace; it does not erase old database records. Recovery/account authentication is planned. Never put service keys in `VITE_*` variables.

Profiles, documents and dashboard data come from the real local backend: unavailable APIs show errors/retry controls, empty databases show empty states, and unimplemented metrics show a dash/planned label. The opportunities page uses an explicitly labeled seeded/mock dataset; public previews and legacy `/workspace` remain illustrative. Saving draft edits and confirming profile facts are separate actions. Extracted suggestions stay outside the profile until confirmation.

## Document review

Upload a readable resume, then choose **Process document**. Processing stays local by default. The optional CrewAI/Groq checkbox explicitly permits sending that document's extracted text, including contact details, to the backend-configured provider for that run. A second unchecked option permits rendered page images for visual layout analysis. Local previews/OCR need no external-image consent. Configured runs execute the actual Resume Intelligence Crew. Agent metadata shows CrewAI processing, local-only processing, or an explicit fallback with its safe reason. Provider keys never reach this app. Missing keys, timeouts, rate limits, and invalid AI JSON retain real local extraction and show limited-mode warnings.

Review source quotes, heuristic confidence, and missing-field warnings. Expand sections to edit, then save draft edits. Select sections to apply and confirm accuracy before **Confirm and save profile**. Lists add unique entries; replacement requires an explicit choice. Different saved scalar values start unselected. Profile/draft revision conflicts require reload and renewed review. Edited values are labeled candidate corrections rather than claimed document quotes.

Only selected, confirmed sections reach the profile. Dashboard counts derive from stored profile facts and review receipts. Scanned PDFs use local OCR when available, with separate source labels and manual-review warnings. Confirmed-profile matching is available; live job retrieval and the broader career orchestrator remain planned. Local extraction handles basic headings/records and may miss complex layouts; the UI clearly labels its limits. Selection and replacement operate per top-level section, not per individual nested record.

## Search and filter diagnostics

The Bengaluru/AI zero-result audit fixed combined city/country normalization, Bangalore aliases, controlled AI-family retrieval and saved-threshold overrides. The frontend defaults to city plus country-compatible remote roles, with explicit exact-city/state/country choices under **More search filters**. Selecting onsite still excludes remote roles. A separate role field accepts AI/ML/NLP and related vocabulary; category scope can be restricted to an exact category.

Both threshold controls accept fractional **0–100 raw points**. `0.5` is half a point, `50` is fifty points, and a result threshold of zero can reveal previously scored rows below the saved threshold. Hard-filter changes require a fresh run. Historical runs are preserved and labelled when they lack current diagnostics.

Expand **Matching audit → Search and filter diagnostics** for request parameters, normalized filters and counts at each stage. Excluded-job JSON previews are bounded to 100 rows and searchable by job ID/reason. Cards explain location and role eligibility separately from candidate skill evidence. ## Application preparation and tracking

Create the record, prepare it from current confirmed facts, enter missing information, review every populated field, and explicitly choose documents. Saving a review is separate from approving the exact prefill snapshot and starting the MCP operation. Edits reset approval; changed profile facts require fresh preparation.

The current job provider is synthetic, so the default MCP app is a clearly labelled **local demo**. It runs a real stdio server and official MCP Apps iframe bridge. The demo records approved values/files without contacting an employer. Submission is never automatic: the external adapter contract supports prefill only, and a submission record always comes from the user's explicit acknowledgement. Demo completion remains labelled simulated. Notes, deadlines, follow-ups, interviews and outcomes are stored in the private sequenced timeline.

The native form uses an allowlisted server-defined schema and A2UI interaction messages. Expand the audit for the actual CrewAI Flow, optional six-agent Groq review, evidence, validation, approval digest, MCP receipt and discovered tools. The optional model review exports redacted field/type/classification metadata, never candidate values or document text. Missing model/MCP UI support leaves a usable native local review interface. The sandboxed resource can save a draft through the host, but it cannot approve, prefill, upload or submit independently.
